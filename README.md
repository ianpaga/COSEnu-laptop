# COSEnu on a laptop
(by Ian Padilla-Gay and collaborators)

COSEnu is a numerical code for studying collective neutrino flavor evolution
in dense astrophysical environments, such as core-collapse supernovae and
neutron-star mergers. This repository packages a student-friendly, CPU-only
version that compiles, runs, and analyzes simulations on a laptop without
Slurm or a cluster account.

## What the code does

The code evolves the two-flavor neutrino and antineutrino density matrices
`rho` and `rhobar` in one spatial dimension `z` and one propagation-direction
coordinate `v_z`. In schematic form, it solves

```text
(partial_t + v_z partial_z) rho = -i [H, rho] + C[rho],
H = H_vac + H_mat + H_nunu,
```

with an analogous equation for antineutrinos. The Hamiltonian contains vacuum
mixing, ordinary-matter refraction, and nonlinear neutrino-neutrino forward
scattering; the optional collision term damps flavor coherence. The default
calculation is monoenergetic. With `MULTIENERGY=true`, the code evolves a
pinched energy spectrum and accounts for the `1/E` dependence of the vacuum
oscillation frequency.

The supplied configurations illustrate vacuum oscillations, slow collective
oscillations, fast flavor conversion, collisional flavor instability (CFI),
and multi-energy evolution. The optional linear stability analysis (LSA)
finds unstable normal modes and predicts their exponential growth rates for
direct comparison with the nonlinear simulation. The analysis scripts produce
survival probabilities, flavor coherence, angular moments and distributions,
Fourier spectra, space-time maps, Hamiltonian scales, conservation diagnostics,
and energy-resolved figures when applicable.

### Scientific background

In a sufficiently dense neutrino gas, coherent forward scattering between
neutrinos makes the flavor equations nonlinear: each angular and energy mode
evolves in the flavor field generated by all the others. This permits
collective behavior that is qualitatively different from independent vacuum
oscillations. Slow modes involve the vacuum scale `omega = Delta m^2/(2E)`,
whereas fast modes can grow on the much shorter self-interaction scale `MU`;
the supplied fast example contains an electron-lepton-number angular crossing.
Unequal neutrino and antineutrino collision rates can also destabilize an
otherwise crossing-free gas, as illustrated by the CFI example.

Unless stated otherwise, the simulation uses `MU=1`: Hamiltonian frequencies
are expressed in units of `MU`, while time and distance are in `MU^-1`.
This is a controlled two-flavor, one-dimensional mean-field model intended for
research experiments and teaching. It is not a complete supernova or merger
radiation-transport calculation, and its damping prescription is not a general
neutrino collision integral.

## Run it

Open a terminal in this folder and run:

```bash
./cosenu.sh run
```

If an archive has lost executable permissions, use `bash cosenu.sh run` instead.

The launcher automatically:

1. Checks for a C++ compiler and offers to install it if necessary.
2. Compiles COSEnu in a disposable build directory.
3. Runs the simulation locally using the settings in `laptop.conf`.
4. Installs the plotting packages in an isolated environment when needed.
5. Generates the standard analysis plots when `PLOTS=yes`.
6. Optionally runs the linear stability analysis when
   `LINEAR_STABILITY_ANALYSIS=true`.

The configuration reproduces the active research settings from the old
parameter scan. This is a substantial calculation (`NZ=500`, `NVZ=256`, and
`END_TIME=500`), so the launcher shows a laptop-resource warning before it
starts. Reducing those three values is useful for short experiments.

To install/check the requirements without starting a simulation:

```bash
./cosenu.sh setup
```

On Windows, first install
[Windows Subsystem for Linux (WSL)](https://learn.microsoft.com/windows/wsl/install)
and use these same commands inside WSL.

## Configuration

Edit [`laptop.conf`](laptop.conf), then run `./cosenu.sh run` again. It contains
the grid, physical parameters, initial angular distributions, collision terms,
boundary conditions, and output frequency.

The supplied values combine the active values from the former
`parameter_scan.sh` with the remaining settings from
`cosenu_configs.yaml`:

- `ALPHA=0.85`, widths `0.6`, and deterministic central seeds
- domain `[-100, 100]`, `NZ=500`, `NVZ=256`, and `CFL=0.4`
- normal ordering, `OMEGA=1e-2`, `MU=1`, and `END_TIME=500`
- vacuum and collective oscillations on; matter oscillations off
- matter slope/offset and collision terms set to zero
- 200 analysis records and 50 density snapshots
- power spectrum sampled over `-K_MAX <= k <= K_MAX` using `K_BINS` points

The compact `rho_*.npy` snapshots are about 9.8 MiB each on this grid. Fifty
requested snapshots plus the initial state occupy about 498 MiB; allowing about
0.55 GiB covers the complete run's checkpoints, diagnostics, and plots. On the
development M4 Pro, the solver takes approximately 14 minutes with the default
12-thread limit; runtime varies across laptops.

The supplied spectrum settings are `K_MAX=2` and `K_BINS=1000`. Because
`k` is an angular wavenumber, it must remain below the grid's Nyquist limit
`pi/dz`. The supplied grid resolves this range. The launcher prints a warning
and the minimum suitable `NZ` if a requested range is too wide.

### Configuration templates

The `conf_templates` directory contains the established validation cases,
two matter-gradient experiments, and a laptop multi-energy benchmark. The slow, fast,
and CFI cases were checked directly against the LSA; the vacuum-only case was
checked against the analytic two-flavor probability:

```bash
./cosenu.sh run conf_templates/slow.conf
./cosenu.sh run conf_templates/fast.conf
./cosenu.sh run conf_templates/cfi.conf
./cosenu.sh run conf_templates/vacuum.conf
./cosenu.sh run conf_templates/multienergy.conf
./cosenu.sh run conf_templates/inhom_matter_slow.conf
./cosenu.sh run conf_templates/inhom_slow_soumya_twobeam.conf
./cosenu.sh run conf_templates/inhom_slow_soumya_continuous.conf
./cosenu.sh run conf_templates/inhom_paper_fast.conf
```

`slow.conf` is a copy of the supplied `laptop.conf`. `fast.conf` uses
`OMEGA=0` and a deep ELN angular crossing. `cfi.conf` uses `OMEGA=0`, no ELN
crossing, and unequal neutrino/antineutrino damping rates. `vacuum.conf`
uses `OMEGA=1e-5` and disables self-interactions, matter, collisions,
advection, and the LSA. The first three retain `NZ=500` and `NVZ=256`.
The vacuum solution is exactly homogeneous, so its compact `16 x 16` grid
avoids repeating the same ODE while its longer `2e6 MU^-1` timescale is
resolved. It spans about 3.18 vacuum-oscillation periods and remains a quick
laptop test.

`inhom_matter_slow.conf` is the slow configuration with
`lambda(z)=MATTER_OFFSET+MATTER_SLOPE*(z-Z_MIN)` and
`MATTER_SLOPE=0.005 MU^2`. It preserves `dz=0.4` and `NVZ=256`, widens the
periodic box to `[-250,250] MU^-1`, and ends at `t=200 MU^-1`; the light cone
therefore cannot encounter the discontinuity where the linear profile wraps.
Its 51 compact snapshots need about 1.22 GiB, so allow roughly 1.3 GiB for the
run. For a controlled homogeneous reference, copy the template and change
only `MATTER_SLOPE=0`. A boundary-safe reduced-resolution cross-check at
`t=196 MU^-1` gave mean coherence `0.0571` without the gradient and
`3.43e-4` with the configured slope, a suppression factor of about 167.

`inhom_slow_soumya_twobeam.conf` is the slow, two-direction comparison proposed
by Soumya: `omega=0.006`, `theta=1e-5 rad`, inverted ordering, `MU=1`, per-beam
occupations `g_nue=1` and `g_nuebar=0.85`, `z in [-500,500]`, and
`lambda(z)=1+m(z+500)`. Both species occupy `v_z=-1,+1`, so the ELN is positive
in both directions and there is no fast angular crossing. The continuous
template replaces the two directions with COSEnu's normalized forward-peaked
angular distributions; it is an independent physical cross-check, not an exact
discretization of the two-beam model.

These templates use exact matter half-rotations around each RK4 step,
\(\rho_{ex}\to e^{-i\lambda(z)\Delta t/2}\rho_{ex}\) and
\(\bar\rho_{ex}\to e^{+i\lambda(z)\Delta t/2}\bar\rho_{ex}\). This preserves the physical
spatial phase while avoiding artificial damping from explicitly integrating a
rapid local matter rotation.

Matter gradients push power toward increasing `|k|`, so insufficient spatial
resolution can produce a false late-time decrease in coherence. A useful first
check is `t_decay ~= NZ/(m L)`; the simulation should end comfortably before
this estimate, and important results should be repeated at higher `NZ`.
For comparison plots, treat the box-averaged polarization-length error as the
primary accuracy diagnostic; the maximum error mainly flags localized high-`k`
cells. The student-facing plotting tool uses
`Strans = L^-1 integral dz (|rho_ex^+| + |rho_ex^-|)` for the two-beam scan.

The detailed resolution study, validation of the exact rotation, run-to-curve
mapping, and comparison with the supplied legacy figures are kept in
[`docs/soumya_validation.md`](docs/soumya_validation.md). Use the current
templates rather than old exploratory run directories when reproducing the
scan.

`inhom_paper_fast.conf` is a separate, laptop-sized validation of
[arXiv:2504.11316](https://arxiv.org/abs/2504.11316). It uses the exact
two-beam quadrature (`v_z=+1` neutrinos and `v_z=-1` antineutrinos), the
paper's converted domain, seed, duration, and default `m=0.08 cm^-2` slope.
The small `CFL=0.02` is needed because the largest optional paper slopes make
the matter Hamiltonian much faster than the advection timescale. In the
validation scan, the homogeneous case reached normalized `2|rho_ex|=0.01` at about
`0.362 ns`, the `m=0.08 cm^-2` case at about `0.455 ns`, and the
`m=0.30 cm^-2` case remained below `6e-8` through `2.7 ns`, reproducing the
delay and high-gradient suppression seen in the paper. The retained
`NZ=2400` benchmark took about 2.4 minutes and 32 MiB on the development Mac;
its final box-averaged neutrino and antineutrino polarization-norm errors were
`0.19%` and `1.15%`. The paper used `NZ=18000`, but that resolution is not
needed for this student-facing qualitative validation.

### Monoenergetic and multi-energy modes

`MULTIENERGY=false` is the default and runs the original monoenergetic solver
path. The extra configuration entries are ignored in that mode, so existing
slow, fast, CFI, and vacuum calculations retain their previous behavior.

Set `MULTIENERGY=true` to evolve `ENERGY_BINS` neutrino modes and the same
number of antineutrino modes. `ENERGY_GRID=energy` uses a uniform grid between
`ENERGY_MIN` and `ENERGY_MAX` in MeV and is the convenient choice for student
experiments. `ENERGY_GRID=omega` uses a uniform frequency grid and is
provided for direct comparison with the setup in
[arXiv:2608.26847](https://arxiv.org/abs/2608.26847). `OMEGA` is the value of
`omega/MU` at `REFERENCE_ENERGY`; every other frequency scales as `1/E`.

The initial species spectra use the normalized pinched alpha-fit

```text
f_alpha(E) proportional to E^alpha exp[-(alpha+1) E/<E>].
```

Their number normalizations are calculated from
`(L_alpha/<E_alpha>)/(L_nue/<E_nue>)`. `SPECTRAL_ALPHA=2` gives the
Maxwell-Boltzmann-shaped member of this family; `SPECTRAL_ALPHA` around 2.3
matches the first two moments of a zero-chemical-potential Fermi-Dirac
spectrum, while the article validation template uses `SPECTRAL_ALPHA=3`.
`MEAN_ENERGY_*` values are in MeV and the three `LUMINOSITY_*` values may use
any one common unit.

`conf_templates/multienergy.conf` contains the article's late-accretion
spectrum and frequency range with reduced laptop grids. On a reduced
`N_omega=40`, `N_v=40` cross-check, the multi-energy LSA gives growth rates
`0.09119 MU` (normal ordering) and `0.23495 MU` (inverted ordering) at
`k=+0.08 MU`, consistent with the published `0.091` and `0.23`. Comments in
the template give the much larger publication-resolution values; those need
roughly 15 GiB just for the four Runge-Kutta states and are not a normal laptop
run. A separate deliberately coarse nonlinear check measured `0.0844 MU`
versus the LSA prediction `0.0875 MU` (3.6% difference).

For efficient output, new energy-integrated spatial snapshots are saved as
compact NumPy arrays named `rho_*.npy`. They contain `z`, `v_z`, and the eight
density-matrix components; the plotting code reconstructs polarization vectors
as needed and also accepts legacy `rho_*.dat` files. Each saved snapshot gets a
small `energy_*.dat` table averaged over both space and angle and an
`energy_angle_*.dat` table averaged over space. Only `state.bin`, used for
restart, stores the complete energy-angle-space state. Its size increases
linearly with `ENERGY_BINS`, `NVZ`, and `NZ`.

### Multi-energy laptop resource guide

For the supplied `conf_templates/multienergy.conf` settings
(`ENERGY_BINS=48` per sector, `NZ=1000`, `NVZ=64`, `SNAPSHOTS=25`, and
`ANALYSES=200`), a typical run uses approximately:

- 0.8--0.9 GB of RAM while the C++ solver is running;
- 150--300 MB of RAM while Python plotting or the LSA is running;
- 350--450 MB of saved data and figures per completed run; and
- about 189 MB for the restart checkpoint.

Allowing **1.2 GB of available RAM and 600 MB of disk space per run** is a
comfortable working budget. The automatically installed Python plotting
environment needs an additional one-time 150--300 MB of disk space. A laptop
with at least 4 GB of total system RAM and a few GB of free storage should run
this template comfortably.

Solver memory scales approximately as
`(2 * ENERGY_BINS) * NVZ * NZ`; the factor of two accounts for neutrino and
antineutrino energy modes. Per-run storage is controlled mainly by
`SNAPSHOTS`, while the power-spectrum output also grows with `ANALYSES` and
`K_BINS`. Old timestamped directories under `runs/` continue to occupy space
until they are removed. The commented publication-resolution grids are not
laptop settings: they require roughly 15 GiB for the Runge--Kutta states alone
and several additional GiB of output.

The convergence test used `NZ=1000` and `NVZ=64`. At `t=200`, its
spectrum-weighted neutrino and antineutrino polarization-norm errors were
`0.14%` and `0.18%`, respectively. `NZ=500` left errors around `1.2--1.6%`;
doubling `NVZ` beyond 64 or halving `CFL` did not materially improve them.

During a multi-energy run, each 1% progress line also checks the combined,
spectrum- and box-averaged polarization-norm error. If
`<dP>_total > 0.1` (a 10% error), the line is marked with a warning and prints
the current value. Healthy runs remain uncluttered.

For multi-energy runs, the right conservation panel tracks the global
mass-basis lepton-number projection. This is the correct invariant for the
inhomogeneous periodic system when matter and collisions are absent. The
former local mean-field-energy expression is not conserved in the presence
of streaming and produced a misleading jump during nonlinear evolution.

## Automatic plots

The setting in `laptop.conf` is:

```bash
PLOTS=yes
```

With `yes`, plots are generated immediately after a successful simulation.
NumPy and Matplotlib are installed automatically under `build/plot-env`; they
do not alter the computer's main Python installation. Set `PLOTS=no` to skip
the standard plots. Python setup is skipped entirely when both `PLOTS=no` and
`LINEAR_STABILITY_ANALYSIS=false`.

All plots are PDF files. Their lower axes use the simulation units `MU^-1`.
Every time-based plot also has an upper physical-time axis in microseconds, and
the phase-space plots have upper physical-distance axes in meters. The
configured `OMEGA` is interpreted directly as `omega/MU`. Assuming physical
`omega=0.63 km^-1` for a 10 MeV neutrino (with the usual `1/E` scaling) and
`c=299.792458 m/microsecond`, the program infers
`MU=0.63/OMEGA km^-1` when `REFERENCE_ENERGY=10 MeV` (and applies the `1/E`
factor for another reference energy). Changing either setting therefore
updates all physical axes automatically.

The `plots` folder inside each run contains PDF files for:

- survival and conversion probabilities
- conservation diagnostics
- angular moments
- initial, final, and steady-time-averaged electron-flavor angular distributions
- power spectra at five representative times
- initial and final electron-lepton-number/flavor snapshots
- initial and final `rho_ex` phase maps on the `z-v_z` plane
- `rhoex_z_initial.pdf` and `rhoex_z_final.pdf`: the real and imaginary parts
  of `rho_ex` versus `z` in two panels at up to six evenly spaced velocity
  bins, including both ends of the saved velocity grid (all bins for smaller grids). Multi-energy
  runs use the already energy-integrated snapshots, retaining each velocity
  bin separately.
- velocity-averaged initial/final self-interaction, matter, and vacuum
  Hamiltonian scales along `z`
- mean off-diagonal coherence
- for nonzero linear matter slopes, the homogeneous LSA growth band and the
  swept-wavenumber estimate `k_eff=k-(d lambda/dz)t`, compared with COSEnu
  in `matter_gradient.pdf`
- a three-panel time-position figure containing the local neutrino survival
  probability plus the magnitude and phase of the complex `v_z`-integrated
  coherence, including physical axes and the `z=+/-ct` light cone
- for `ANGULAR_PROFILE=symmetric_two_beam` or `soumya_two_beam`, an additional
  time-position map of normalized velocity-integrated antineutrino coherence
- for a multi-slope Soumya comparison made with
  `analysis/soumya_matter_scan.py`, both the velocity-integrated map and the
  exact `v_z=+1` antineutrino diagnostic shown by the supplied legacy figures
- a text summary of the run

A multi-energy run additionally creates:

- `energy_spectra.pdf`: initial and final electron/heavy-flavor number spectra
- `energy_survival.pdf`: neutrino and antineutrino survival probability versus
  energy and time
- `energy_angle.pdf`: the final `P3(E,v_z)` phase-space maps
- `lepton_spectrum.pdf`: initial and final E-XLN spectra and crossings

For the pure vacuum template, the survival/conversion figure additionally
overlays the analytic result
`Pee = 1 - sin^2(2 theta) sin^2(omega t / 2)` and its complementary transition
probability. This overlay is enabled only when vacuum oscillations are on,
self-interactions and matter are off, the damping rate is zero, and
`PERTURBATION_SIZE=0`. The terminal and `summary.txt` report the maximum
absolute difference between COSEnu and the analytic probability.

`T_STEADY` in `laptop.conf` selects when the angular-distribution time average
begins, in `MU^-1`; its supplied value is `300`. The average starts at the
saved density snapshot nearest that time and includes every later snapshot.
Increasing `SNAPSHOTS` improves its time resolution but also increases disk
usage.

`plots/power_spectrum.pdf` follows the presentation of Fig. 9 in
[arXiv:2604.06404](https://arxiv.org/abs/2604.06404): it shows the time-colored
spatial Fourier power of the velocity-integrated `rho_ee`, `rho_xx`, and
`rho_ex`. When LSA results are available, the `rho_ex` panel also shows the
normalized growth-rate dispersion and an orange marker at its most unstable
mode.

Plots can be generated again later with:

```bash
./cosenu.sh plot runs/laptop-20260903-191021
```

## Linear stability analysis

The LSA is optional. To run it automatically after each successful COSEnu
simulation, edit `laptop.conf` to use:

```bash
LINEAR_STABILITY_ANALYSIS=true
LSA_NVZ=200
LSA_NUM=50
LSA_K_MIN=-0.5
LSA_K_MAX=0.5
```

`LSA_NVZ` is an independent angular resolution and does not change COSEnu's
`NVZ`. `LSA_NUM` is the number of sampled wavenumbers (the variable called
`num` in the legacy program). The supplied k interval reproduces the active
legacy LSA setup and lies inside the COSEnu power-spectrum interval.

All remaining inputs are read from the same run: the neutrino and
antineutrino angular distributions, `ALPHA`, `OMEGA`, mass ordering, mixing
angle, `MU`, matter potential, and collision terms. For a spatially varying
matter profile, the homogeneous LSA uses the potential at the center of the
COSEnu box. A constant matter potential shifts `Re(Omega)` but not the growth
rate. When `MATTER_SLOPE` is nonzero, each mode instead samples
`Im(Omega[k-(d lambda/dz)t])`; the plotting routine integrates this rate and
creates `matter_gradient.pdf`. It intentionally omits the ordinary
constant-rate `coherence_comparison.pdf`, which would be physically
inapplicable to the gradient run.

When `MULTIENERGY=true`, the LSA reads the exact frequencies and
quadrature weights written by COSEnu. The discretized self-interaction is a
rank-2 update, so the analysis solves the corresponding 2-by-2 dispersion
determinant instead of allocating and diagonalizing the full
`(N_omega*N_v)^2` dense matrix. `LSA_NVZ` and `LSA_NUM` remain independently
selectable; the LSA energy grid deliberately remains identical to the
simulation's energy grid. In this mode, `branches.pdf` evaluates Appendix-C
Eq. (C6) on that discrete spectrum at `kprime=0` and continues each unstable
root with the full energy-angle dispersion determinant.

The optional off-diagonal collision terms work with both `SCHEME=fd` and
`SCHEME=fv`. `DAMPING_RATE` is the neutrino rate (C), while the antineutrino
rate is `ANTINEUTRINO_COLLISION_RATIO * DAMPING_RATE`. The LSA includes the
same two rates as −iC and −iCbar. Consequently, a later CFI experiment can
use `OMEGA=0` and unequal rates even when the angular distributions have no
crossing; equal rates produce common damping rather than a CFI.

The `lsa` folder inside the run contains:

- `background.pdf`: the angular distributions and their difference
- `dispersion.pdf`: the dominant complex frequency versus k
- `branches.pdf`: the corresponding mono- or multi-energy version of
  Appendix-C Fig. 12, resolving unstable frequencies into the two angular branches
  `lambda+` and `lambda-` for both normal and inverted ordering
- `dominant_mode.pdf`: the unstable eigenfunction; multi-energy runs also show
  neutrino and antineutrino velocity slices at the energy bin nearest 15 MeV
- `coherence_comparison.pdf`: the marker-free, spatially integrated neutrino
  coherence (also energy/angle integrated in multi-energy mode) from COSEnu
  and the LSA prediction proportional to
  `exp(Im(Omega)*t)` during linear growth
- `growth_rates.dat`, `dominant_mode.dat`, `branches.dat`, and
  `summary.txt`: numerical results

For a nonzero matter slope, `coherence_comparison.pdf` is replaced by the
gradient-aware `plots/matter_gradient.pdf`. Its upper panel shows the
homogeneous growth band and the motion through it; its lower panel compares
COSEnu with the swept-band linear estimate and the counterfactual homogeneous
estimate. These analytic curves describe only the pre-saturation phase.

The branch figure uses the shifted wavenumber `kprime = k - Jz`, with `Jz`
computed from the initial lepton-number current. It is generated when the
neutrino and antineutrino distributions share the same angular shape, as in
the supplied slow template, and collisions are off. The paper's energy
integral is replaced by this model's two modes in monoenergetic runs and by
the configured quadrature in multi-energy runs; no artificial distribution is
introduced. The diagonal splitting is the same vacuum term used by the full
LSA. The figure is skipped for unequal angular widths (including the fast
template) or nonzero collision rates because the Appendix-C two-branch
factorization does not apply in those cases.

The green COSEnu curve is fit in log space using its exponential region between
1% and 20% of the pre-saturation peak. The red dashed line has the LSA slope
`Im(Omega)` and an independently fitted vertical normalization. The plot and
summary quote both growth rates and their relative difference. The LSA line is
shown only around the linear-growth regime because linear stability theory is
not expected to describe the later nonlinear evolution.

To analyze a completed run later—even if its saved configuration has the LSA
flag set to `false`—run:

```bash
./cosenu.sh lsa runs/laptop-20260903-191021
```

For this standalone command, edit `LSA_NVZ`, `LSA_NUM`, `LSA_K_MIN`, and
`LSA_K_MAX` in the top-level `laptop.conf`. The physical inputs continue to
come from the completed run, ensuring that the LSA is compared with the
simulation that actually produced the data.

The same isolated Python environment used by the standard plots is used for
the LSA. NumPy and Matplotlib are installed there automatically. GSL,
Slurm, MPI, and cluster software are not required.

## Results and other commands

Every simulation gets a new timestamped directory, such as
`runs/laptop-20260903-191021`. Earlier runs are never overwritten.

```bash
./cosenu.sh run                    # build, run, and optionally plot
./cosenu.sh build                  # compile without running
./cosenu.sh run other.conf         # use another configuration
./cosenu.sh restart runs/laptop-20260903-191021  # continue from its checkpoint
./cosenu.sh plot runs/laptop-20260903-191021     # regenerate its analysis plots
./cosenu.sh lsa runs/laptop-20260903-191021      # run/regenerate its LSA
./cosenu.sh help                   # list commands
```

The launcher searches the installed C++ compilers for OpenMP support and uses
the first working option automatically. At startup it prints either
`execution: OpenMP parallel (N CPU threads)` or
`execution: single CPU thread (OpenMP unavailable)`. `THREADS=auto` uses up to
twelve threads; set `THREADS=4`, for example, to choose a fixed limit. If no
OpenMP-capable compiler is present, the same calculation safely runs on one
CPU core.

The multi-energy evolution benefits substantially because its dominant
energy-angle-space loops are parallelized and the contiguous spatial loop is
vectorized. On the development Apple-Silicon laptop, twelve threads were the
fastest tested setting. A representative 24-mode, `NZ=500`, `NVZ=64` test took
2.21 s after these optimizations, versus 3.49 s with the former loop and output
layout at the same thread count (37% less time), with bit-identical diagnostics
and restart state. The exact speedup depends on grid size, processor, and memory
bandwidth. The main Runge--Kutta arrays are shared, so their quoted storage is
not multiplied by the thread count.

For the single-energy `slow.conf` workload, a production-shaped benchmark took
62.67 s with the 12-thread default. Fourteen threads was only 3.6% faster, so
the launcher retains the simpler and more conservative 12-thread automatic
